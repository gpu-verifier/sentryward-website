About the data

A verdict applies to the recorded input configuration and the verifier’s model. It is not a claim about every shape, execution environment, or version of a library.

How verification works
Synchronization-removal methodology

“Removable syncs” counts synchronization sites removed together while the reduced kernel still passed race-freedom verification. Kernel timing is measured on an NVIDIA B200. “Faster” and “slower” describe runtime changes relative to the original kernel, not throughput speedups. Missing values remain distinct from measured zero or no measurable change.

Verification outcomes

Current passes includes verified records and synchronization/memory checks reported as race_free. Open a record to inspect whether reference equivalence was requested. Current findings groups potential races, invalid lifecycles, and inconsistent synchronization; these are verifier findings, not necessarily reproduced hardware failures. Current inconclusive groups unsupported analyses and time, memory, or analysis limits.

Per-check outcomes and analysis statistics appear when supplied by the results JSON. Missing fields are labeled “Not recorded”; “Not run” and “Incomplete” do not mean passed. Each record links to its verifier output for further detail.

Conditional analyses

Some records use configured branch decisions. Their verdicts apply only to those scenarios. Open a marked record to see every recorded branch decision.

Warnings and their collection status are reported independently of the overall verdict.

Source and provenance

This page reads the latest published run from gpu-verifier/sentryward, verifies the snapshot hash, and keeps every record bound to that run. Reload to check for a newer publication.

Each published snapshot binds its inputs, source files, reports and evidence to recorded versions and hashes. Deferred or historical results are not counted as checks of the current target. Missing fields are not filled from an older run.
